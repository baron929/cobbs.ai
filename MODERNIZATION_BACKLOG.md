## Dependency and Migration Rules

- Do not upgrade dependencies merely because a newer version exists.
- Before each dependency change, record current version, target version, security status, license, compatibility, breaking changes, tests, and rollback.
- Do not combine frontend build migration, backend framework migration, database migration, and agent-runtime replacement in one release.
- Use additive database migrations and feature flags for new task/run/device paths.
- Preserve existing provider and tool adapters behind stable interfaces while the control plane changes.
- Do not change Docker owner/domain values until external ownership is confirmed.
